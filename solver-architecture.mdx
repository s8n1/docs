# Solver Architecture / معماری حل‌کننده

The intended product is an **automatic differential-equation solver**, not a tutorial. The user enters an equation and receives the strongest result the system can validate.

محصول هدف یک **حل‌کنندهٔ خودکار معادلات دیفرانسیل** است، نه یک راهنمای آموزشی. کاربر معادله را وارد می‌کند و سیستم قوی‌ترین نتیجهٔ قابل‌اعتبارسنجی را برمی‌گرداند.

## Result policy / سیاست نتیجه

The solver follows this order:

1. Normalize the input into a safe mathematical representation.
2. Classify it against the supported model catalog.
3. Attempt symbolic solving.
4. If no closed form exists, keep descending the answer ladder instead of failing: an exact result with the quadrature left unevaluated (`integral`), the equation integrated once (`implicit`, e.g. the energy integral of `y'' = f(y)`), a Taylor series of the solution around the start of the interval (`series`), or — when the input contains no derivative at all — the algebraic answer (`algebraic`).
5. Fall back to numerical solving when none of the exact forms can be produced.
6. Validate the result with residuals, initial/boundary conditions, convergence, and solver diagnostics.
7. Return a complete answer, an approximate answer, or the furthest verified partial result with a technical reason.

The `residual` reported with a numerical answer is the accuracy actually achieved: the same problem is integrated again at tolerances two orders of magnitude tighter, and the largest deviation from that reference is reported. It therefore describes the integration rather than the sampling grid — a fast or stiff system that is solved correctly reports a small value, and asking for more points does not change it. `null` means no reference could be produced, and the answer is marked unverified rather than given a number.

Both the symbolic sweep and the numerical integration run under hard time, memory, step-count and magnitude caps, so a singular equation such as `y' = tan(y)` is bounded rather than hanging the request.

ترتیب پردازش:

1. تبدیل ورودی به نمایش ریاضی امن
2. تشخیص مدل از میان مدل‌های پشتیبانی‌شده
3. تلاش برای حل نمادین
4. در صورت نبود جواب بسته، نردبان جواب ادامه می‌یابد: جواب دقیق با انتگرال بازمانده (`integral`)، معادلهٔ یک بار انتگرال‌گیری‌شده (`implicit`، مانند انتگرال انرژی برای `y'' = f(y)`) یا بسط تیلور جواب (`series`)؛ اگر ورودی هیچ مشتقی نداشته باشد، جواب جبری (`algebraic`)
5. در نهایت، استفاده از حل عددی
6. بررسی residual، شرایط اولیه/مرزی، همگرایی و خطا
7. ارائهٔ جواب کامل، تقریبی یا بیشترین نتیجهٔ معتبر به‌همراه دلیل فنی

مقدار `residual` که همراه جواب عددی گزارش می‌شود، همان دقت واقعی به‌دست‌آمده است: همان مسئله با تلورانسی صد برابر سخت‌گیرانه‌تر یک بار دیگر حل می‌شود و بیشترین اختلاف با آن مرجع گزارش می‌گردد. پس این عدد به شبکهٔ نمونه‌برداری بستگی ندارد و دستگاه سریع یا سخت که درست حل شده باشد، مقدار کوچکی نشان می‌دهد؛ تعداد نقاط بیشتر هم آن را تغییر نمی‌دهد. مقدار `null` یعنی مرجعی تولید نشده و جواب «تأییدنشده» علامت می‌خورد، نه اینکه عددی از خود ساخته شود.

حل نمادین و حل عددی هر دو با محدودیت زمان، حافظه، تعداد گام و بزرگی مقدار اجرا می‌شوند؛ بنابراین معادله‌های تکین مانند `y' = tan(y)` به‌جای معطل‌گذاشتن درخواست، محدود می‌شوند.

## Skills layer / لایهٔ مهارت‌ها

Alongside the 42 model families, the engine exposes a registry of independently
callable skills (`api/skills.py`): a Riccati reduction, a power-series solution, a
Frobenius series, equilibria with Jacobian classification, the Lyapunov spectrum,
a bifurcation sweep, a sensitivity analysis and a stiffness scan. Each skill has
an id, a bilingual description, a token price and one entry point, and each
returns the same payload shape as the free-form solver. Two of them are the same
functions the exact solver already calls internally, so the classification layer
can name the method it intends to use before spending tokens on it. See the
[Solver skills](/skills) page for the catalog and the endpoints.

در کنار ۴۲ خانوادهٔ مدل، موتور فهرستی از مهارت‌های مستقل (`api/skills.py`) ارائه
می‌دهد: کاهش ریکاتی، جواب سری توانی، سری فروبنیوس، نقاط تعادل با طبقه‌بندی ژاکوبی،
طیف لیاپانوف، جاروب دوشاخگی، تحلیل حساسیت و بررسی سختی. هر مهارت شناسهٔ یکتا،
توضیح دوزبانه، قیمت توکنی و یک نقطهٔ ورود دارد و قالب خروجی آن با حل‌کنندهٔ آزاد یکی است.

## Stiff and multivariable systems / سیستم‌های stiff و چندمتغیره

For systems such as `y' = f(t, y)` with many state variables, the numerical engine selects appropriate methods and tolerances. Stiff problems use implicit methods such as BDF or Radau, with bounded step counts and wall time. Results include the selected method, tolerances, status, and error estimates.

برای سیستم‌های چندمتغیره، روش‌های عددی مناسب با توجه به stiff بودن مسئله انتخاب می‌شوند. برای مسائل stiff از روش‌های ضمنی مانند BDF یا Radau استفاده می‌شود و تعداد گام، زمان اجرا و منابع محدود خواهند بود.

## AI responsibility / نقش هوش مصنوعی

AI may interpret natural language, identify variables and conditions, and explain verified output in Persian or English. It must not invent a solution or execute generated code. The numerical engine is the authority, and every answer must carry verification metadata.

هوش مصنوعی زبان طبیعی را تفسیر می‌کند، متغیرها و شرایط را تشخیص می‌دهد و نتیجهٔ معتبر را توضیح می‌دهد؛ اما حق ساختن جواب بدون بررسی یا اجرای کد تولیدشده را ندارد.

## 42 supported families

The implementation roadmap covers 42 explicit model families, including separable, exact, linear, Bernoulli, Riccati, autonomous, logistic, homogeneous, higher-order constant-coefficient, Euler-Cauchy, Laplace, Fourier, systems, stiff systems, BVPs, eigenvalue problems, nonlinear numerical problems, and representative PDE/discretization families. Every family must have a named adapter, supported syntax, limitations, and regression cases before being marked supported.

> “Supported” means the model has an implemented adapter and automated verification tests. It does not mean every arbitrary equation in that family has a closed-form solution.
